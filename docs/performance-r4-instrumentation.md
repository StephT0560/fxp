# Local profiling instrumentation

The round-4 runner is `scripts/profile_r4.py`; its launch environment raises the
per-connection token bucket to 1,000,000 messages/s with a 1,000,000 burst. This
is a benchmark setting, not a production recommendation. All runs pin core to
CPU 0, gateway to CPU 1 and generator to CPU 2. The container has a shared
2-CPU quota despite exposing three affinity CPUs. A bridge shares gateway CPU 1.

All diagnostics are off by default, add no wire fields and expose no HTTP
listener. These files contain order IDs and stack information: store them in a
private directory. Do not enable diagnostics during baseline measurements.

| Process | Variable | Default | Meaning |
|---|---|---|---|
| Core, gateway, bridge, Go benchmark | `FXP_HOP_TRACE` | unset | Local hop-event file (Linux CLOCK_MONOTONIC, ns); buffered, flushed on clean shutdown |
| Gateway, bridge, Go benchmark | `FXP_PROFILE_DIR` | unset | CPU, cumulative allocations, block and mutex pprof files; full block/mutex sampling |
| Gateway, bridge, Go benchmark | `FXP_TRACE_FILE` | unset | Go runtime execution trace file |

Go hop events are JSONL; Rust events are TSV with debug-escaped IDs. The collector
supports the ASCII IDs generated by this harness. Trace only synthetic benchmark
traffic. Traced execution performs file buffering, extra protobuf decode at writer
boundaries, clock reads and locks; it perturbs the workload. Compare untraced
baselines, not instrumented hop totals, when making latency claims.

The ten events are client pre-construction send, gateway receive after decode,
gateway core write before syscall (after acquiring pooled connection lock), core
receive after decode, symbol-task engine start/end, core write before syscall,
gateway core receive after decode, gateway client write before syscall, and
client receive after decode. Thus transport intervals include framing/decode,
scheduling and adjacent timestamp/logging overhead; engine time includes tick,
validation, matching and output construction, not serialization or socket write.
These are application boundaries, not kernel packet timestamps.

`python3 scripts/collect_hops.py benchmarks/round4/hops-open-c1` joins by order ID,
excludes warmup, checks monotonic ordering, and reports median/min/max of per-run
nearest-rank p50/p99. The primary harness retains HDR percentiles. Missing or
duplicate events must be reported; do not hide incomplete orders.

`--subscribers N` adds authenticated active market-data readers to the Go
benchmark, subscribed to every measured symbol. They share the generator CPU.
Subscriptions are acknowledged by snapshots after warmup, before measurement.
The reported update count excludes any updates still in
flight when measurement completes; it is not a delivery-loss or feed-gap metric.
Zero is the default. Slow-reader/drop behavior needs its own dedicated workload.

In Compose, the per-service variables map to container paths; use an explicit
bind mount when collecting files (for example a writable private `/profiles`).
No profiling directory is mounted or created in a default deployment.

Compose path selectors are `FXP_CORE_HOP_TRACE`, `FXP_GW_HOP_TRACE`,
`FXP_FIX_HOP_TRACE`, `FXP_GW_PROFILE_DIR`, `FXP_FIX_PROFILE_DIR`,
`FXP_GW_TRACE_FILE` and `FXP_FIX_TRACE_FILE`, all unset by default.

The optional Cargo feature `dhat` installs a tracking allocator only in that
profiling build. `FXP_DHAT_FILE` chooses its heap output (default
`dhat-heap.json`); it is ignored in ordinary builds. Never compare its latency
or throughput with the normal allocator. Build a separate target directory and
keep binaries outside the committed artifacts. The Engine Criterion fixture
starts with 10,000 buys across 100 price levels, then times 5,000 cancels and
5,000 new resting buys; seed construction is excluded. It measures the Engine
API, including outputs, ID construction and destruction, not networking.

`perf sched record`/`perf sched latency` require scheduler tracepoints. This
container does not mount tracefs; that is independent of CPU sampling support.
Keep the error output rather than substituting a made-up scheduler latency.
A locally extracted Debian perf can record `cpu-clock:u` without changing the
host. The runtime trace supplies Go scheduler-delay evidence but cannot replace
the missing kernel scheduler view.
